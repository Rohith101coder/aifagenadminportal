1.3 The Core Problem It Solves ("Dashboard Sprawl" & Manual Admin Friction)
--------------------------------------------------------------------------
In modern tech talent placement and AI training companies, operational teams
routinely suffer from severe "dashboard sprawl". Managing candidates requires
logging into 6 to 8 disparate tools every day:
1. Razorpay/Stripe for checking subscription invoices and failed recurring renewals.
2. Web scraper servers/APIs to see if job crawlers crashed or hit rate limits.
3. ATS software to verify candidate resume scores, tech stacks, and visa eligibility.
4. Interview management tools to review candidate coding scorecards and recordings.
5. Cloud LLM provider dashboards (Groq / OpenAI) to monitor API token burn.
6. Email marketing / CRM software to blast out digests and candidate status reports.

This fragmentation leads to:
- Wasted administrative hours (copying data between tools, compiling Excel reports).
- Delayed operational responses (not noticing failed payments or broken scrapers).
- Inconsistent candidate communication and lost revenue from expiring plans.

The AIFaGen Labs Admin Portal solves this by centralizing all these disparate
functional verticals into a single, unified, ultra-responsive Single Page
Application (SPA). Furthermore, it provides autonomous AI tools (Voice Agent and
Chatbot) that can execute multi-step reporting, data synthesis, and email dispatch
in seconds upon receiving simple natural language instructions.

1.4 Core Architectural Tenets & Philosophies
-------------------------------------------
1. ZERO CLUTTER, TOTAL CLARITY:
   Every high-level KPI (MRR, candidate placement rate, crawler uptime) down to

2. AUTONOMOUS TOOL EXECUTION:

4. HIGH-AVAILABILITY MULTI-TIER REDUNDANCY:
   - AI Fallback: Groq Cloud (Llama-3.3-70B) -> OpenRouter Cascading Fallback.
   - Mail Fallback: Brevo REST API v3 -> Brevo Nodemailer Direct SMTP.
   - Navigation Fallback: DOM Button Click -> React Router Fallback Route Resolver.

2.2 Vanilla CSS Custom Design System (Why No Tailwind/Bootstrap?)
-----------------------------------------------------------------
The application deliberately avoids heavy utility-class frameworks like Tailwind
or monolithic frameworks like Bootstrap. Instead, it utilizes a custom Vanilla CSS
Design System defined in `src/App.css` and `src/index.css` with modular CSS files
for each page and component.

Why this choice was made:
- Total Design Flexibility: Uncompromised control over complex visual requirements,
  such as glassmorphism, multi-stop gradient borders, custom scrollbars, and
  custom-tailored SVG trend graph styling.
- Zero Runtime CSS Bloat: No thousands of utility classes compiled into bloated
  style trees.
- Comprehensive Dark/Light Theming: Implemented via native CSS custom properties
  (`--bg-primary`, `--bg-secondary`, `--card-bg`, `--text-primary`, `--border-color`,
  `--accent-blue`, etc.) governed by the top-level `[data-theme="dark"]` attribute.
  Theme switching is instantaneous without recalculating CSS bundles.

2.3 Document Generation Engines (PDF, AutoTable, Excel/CSV)
-----------------------------------------------------------
- jsPDF 4.2.1: Client-side vector PDF generation library. It renders crisp,
  multi-page business documents directly inside the browser memory without
  requiring an expensive external backend rendering service.
- jspdf-autotable 5.0.9: jsPDF plugin that auto-formats complex datasets into
  beautiful tabular layouts with header fills, alternating zebra striping, custom
  padding, and automatic page breaks.
- Native UTF-8 BOM CSV Engine: Custom spreadsheet generator that prepends the
  Byte Order Mark (`\uFEFF`) to comma-separated text strings. This ensures that
  when exported CSV files are opened in Microsoft Excel (Windows/Mac) or Google
  Sheets, UTF-8 characters (such as currency symbols like ₹, names with accents,
  or bullet points) render correctly without character corruption.

2.4 Speech & Voice Processing Technologies
------------------------------------------
- HTML5 Web Speech Recognition API (`webkitSpeechRecognition` / `SpeechRecognition`):
  Utilizes the native browser speech engine to capture continuous user microphone
  audio streams, perform real-time speech-to-text transcription, and trigger intent
  classification.
- HTML5 Web Speech Synthesis API (`window.speechSynthesis`):
  Utilizes native browser text-to-speech voices to provide immediate spoken audio
  feedback to the administrator upon task completion or navigation.

2.5 Multi-Tier AI Inference Architecture (Groq + OpenRouter Fallback)
---------------------------------------------------------------------
The portal does not rely on a single fragile LLM provider. It implements a resilient
two-tier cascading inference pipeline:

1. Primary Provider - Groq Cloud API:
   - Model: `llama-3.3-70b-versatile`
   - Inference Latency: 250ms - 450ms.
   - Purpose: Real-time voice intent classification, fast tool routing, and instant
     chatbot conversation streaming.
2. Secondary Provider - OpenRouter API:
   - Fallback cascading models:
     a) `meta-llama/llama-3.3-70b-instruct:free`
     b) `mistralai/mistral-small-3-instruct-2409`
     c) `google/gemini-2.0-flash-exp`
   - Purpose: If Groq experiences rate limiting, network timeout, or service
     disruption, the application automatically catches the error and queries
     OpenRouter without breaking the user experience.

2.6 Dual Email Transport Architecture (Brevo REST API v3 + Direct SMTP)
-----------------------------------------------------------------------
Sending transactional reports with large binary attachments (PDF & CSV) from a
client-side React application presents security and networking challenges:

1. Primary Transport - Brevo Transactional REST API v3:
   - Dispatched via server middleware (`/api/send-email`) running in Vite dev server
     and as a Vercel serverless function in production.
   - Payload: JSON with Base64-encoded PDF and CSV attachments.
   - Advantage: REST API requests are authenticated via `api-key` and have NO IP
     address whitelist restrictions. This ensures 100% reliable delivery from
     cloud serverless environments (like Vercel or AWS) which have dynamic IPs.
2. Fallback Transport - Nodemailer Direct SMTP:
   - Configured for `smtp-relay.brevo.com` on port 587.
   - Purpose: Serves as a backup if the REST API key is unavailable or during
     local testing.
   - Gotcha Handled: If Brevo rejects the dynamic IP with SMTP code 525, the code
     catches the error and returns a clear, actionable diagnostic message.

6.1 mailService.js (Universal Reporting & Brevo Email Dispatcher)
-----------------------------------------------------------------
- File Path: `src/services/mailService.js`
- Key Exported Functions:
  1. `sendEmailTool({ toEmail, subject, htmlContent, text, attachments })`
  2. `analyzeAndExtractDataForQuery(userQuery)`
  3. `buildDynamicReportHtml(analyzedData, recipientEmail)`
  4. `buildDynamicExcel(analyzedData)`
  5. `buildDynamicPdf(analyzedData)`
  6. `downloadFile(filename, content, mimeType)`
  7. `executeUniversalReportWorkflow({ userQuery, recipientEmail, onProgress })`
  8. `executeInterviewReportWorkflow({ recipientEmail, onProgress })`

- How It Works:
  - Step 1 (Query Analysis): Inspects the spoken or typed user prompt using semantic
    pattern matching to determine which domain is requested (Interviews, Payments,
    Users, Jobs, Crawlers, AI Telemetry, Team, Audit, Settings, Dashboard).
  - Step 2 (Data Extraction): Pulls fresh records directly from the corresponding
    data registry in `src/data/`.
  - Step 3 (HTML Assembly): Constructs a responsive HTML email containing corporate
    navy headers, KPI summary blocks, formatted data tables, and an official AIFaGen
    corporate footer.
  - Step 4 (Document Generation):
    - Generates an Excel-compatible CSV with UTF-8 BOM encoding.
    - Generates an executive PDF document using `jsPDF` and `jspdf-autotable`
      with auto-wrapping table cells, page numbers, and confidential footers.
  - Step 5 (Secure Cloud Dispatch): Dispatches the payload through the serverless
    proxy (`/api/send-email`), using Brevo REST API v3 as primary, and falling
    back to Brevo SMTP via Nodemailer.

6.2 voiceAgentService.js (Voice Intent & Action Router)
-------------------------------------------------------
- File Path: `src/services/voiceAgentService.js`
- Key Exported Functions:
  1. `determineActionFromVoice(transcript, metadata)`
  2. `executeAgentAction(actionResult, callbacks)`

- How It Works:
  - Takes raw transcribed text from the Web Speech API and matches it against
    `sidebarMetadata.js` using fast regex heuristics and ultra-fast LLM inference
    (Groq Llama-3.3-70B with OpenRouter fallback).
  - Returns a structured action object:
    `{ action: "NAVIGATE" | "SEND_EMAIL" | "CONTROL", id, path, feedback }`.
  - Executes the action: navigates to routes, toggles themes, or triggers
    `executeUniversalReportWorkflow`.

6.3 chatbotService.js (Executive AI Operations Co-Pilot)
--------------------------------------------------------
- File Path: `src/services/chatbotService.js`
- Key Exported Functions:
  1. `getApplicationContext()`
  2. `cleanChatbotResponse(text)`
  3. `sendChatMessage(messages)`

- How It Works:
  - Assembles fresh, sanitized snapshots of all platform data (MRR, candidate roster,
    job crawlers, failed transactions, team headcount, AI token burn).
  - Applies strict PII masking (phones formatted as `(•••) •••-1234`, emails
    formatted as `ro••••@domain.com`).
  - Injects strict platform guardrails (rejects non-platform queries like recipes
    or general trivia).
  - Queries Groq Cloud with OpenRouter fallback.
  - Cleans the output using `cleanChatbotResponse` to strip distracting markdown
    asterisks, hashtags, and raw symbols for clean presentation.

8.1 The Autonomous AI Voice Agent & Universal Email Dispatcher
--------------------------------------------------------------
The Voice Agent transforms administrative reporting:
1. Spoken Audio Capture: Administrator clicks the floating microphone and speaks:
   "Mail me the last 7 days interview reports to rohith.p@aifagenlabs.com".
2. Intent & Email Extraction: `determineActionFromVoice` detects the mail keyword,
   extracts the target email address, and triggers `send_universal_report`.
3. Data Synthesis: `analyzeAndExtractDataForQuery` pulls live interview scorecards
   and candidates from `interviewsData.js`.
4. Document Generation: Generates an Excel-compatible CSV and vector PDF document.
5. Cloud Dispatch: Dispatches via Brevo REST API v3 via `/api/send-email`.

9. CRITICAL POINTS TO REMEMBER, GOTCHAS & SECURITY SAFEGUARDS
================================================================================

9.1 Brevo Email Sender Verification Rules:
    Brevo's transactional email service enforces strict sender verification.
    The sender email address MUST be an authorized, verified sender inside the
    Brevo account (such as `rohithvadla07@gmail.com`). Using unverified addresses
    like `support@aifagenlabs.com` before domain validation will cause Brevo to
    reject delivery with HTTP 400.

9.2 Brevo SMTP Error 525 on Dynamic Cloud IPs:
    Cloud serverless hosts (like Vercel or AWS Lambda) assign dynamic outbound IP
    addresses. Brevo's SMTP relay (`smtp-relay.brevo.com`) rejects connections from
    unrecognized dynamic IPs with error `525 5.7.13 Unauthorized IP address`.
    CRITICAL SOLUTION: The codebase prioritizes Brevo REST API v3
    (`https://api.brevo.com/v3/smtp/email`), which authenticates via `api-key`
    and has NO IP restrictions. Ensure `BREVO_API_KEY` is configured in production.

9.3 Web Speech API Chromium Engine Requirement:
    The HTML5 Web Speech Recognition API (`webkitSpeechRecognition`) is natively
    supported in Chromium-based browsers (Google Chrome, Microsoft Edge, Brave,
    Opera). Mozilla Firefox and some versions of Safari do not support speech
    recognition out of the box. Administrators should use Chrome or Edge for voice
    features.

9.4 PII Masking Safeguards Before LLM Context Injection:
    To comply with privacy laws, candidate phone numbers and emails are masked in
    `src/services/chatbotService.js` before being sent to external LLMs. Candidate
    identities are never leaked in unmasked form to external AI APIs.

9.5 Chatbot Response Sanitizer:
    Raw LLM outputs often contain markdown formatting symbols (`***bold***`,
    `### Header`, `#hashtag`, emojis). The `cleanChatbotResponse` function strips
    these artifacts to maintain a polished, professional executive aesthetic.

9.6 Voice Navigation Fallback Architecture:
    When a voice navigation command is issued, the system first attempts to find
    and click the matching DOM button on the sidebar. If the sidebar is collapsed
    or the element is not found, the `handleVoiceNavigateFallback` handler in
    `App.jsx` resolves the route string and executes `navigate(path)` programmatically.

9.7 LocalStorage Keys & Session Lifecycle:
    The application relies on three primary `localStorage` keys:
    - `aifagen-admin-session`: Stores active user session JSON. Removing it logs out.
    - `aifagen-theme`: Stores theme preference ("dark" or "light").
    - `aifagen_recipient_email`: Stores the default email recipient for voice reports.

9.8 Graph Tooltip Viewport Boundary Clamping:
    When hovering over the Revenue chart on extreme left or right data points,
    floating tooltips can overflow the viewport and create horizontal scrollbars.
    The component clamps the tooltip offset (`Math.max(12, Math.min(x, width - 220))`)
    to keep it fully visible within the container.
